# Heltec Vision Master E290-HF

The E290-HF is the primary full-appliance target. The supported configuration
uses:

- ESP32-S3R8 with an 8 MiB octal-PSRAM design floor;
- 16 MiB external flash;
- HT-RA62-HF with an SX1262 and an 863–928 MHz fitted RF path;
- a DEPG0290BNS800F6 296×128 monochrome e-paper panel; and
- native USB Serial/JTAG for development logs and flashing.

Do not use the firmware on the E290-LF variant. Confirm the module marking and
attach an antenna suitable for the configured frequency before booting an
RF-capable image.

## Pin ownership

| Function | GPIO |
| --- | ---: |
| E-paper data / clock / chip select | 1 / 2 / 3 |
| E-paper D/C / reset / busy | 4 / 5 / 6 |
| Battery ADC | 7 |
| LoRa NSS / SCK / MOSI / MISO | 8 / 9 / 10 / 11 |
| LoRa reset / busy / DIO1 | 12 / 13 / 14 |
| E-paper switched 3.3 V enable | 18 |
| Native USB D− / D+ | 19 / 20 |
| Active-low user key | 21 |
| QuickLink SCL / SDA | 38 / 39 |
| UART TX / RX | 43 / 44 |

The board crate owns these assignments as one collision-tested table. USB
Serial/JTAG and USB OTG share GPIO19/20 and cannot be treated as simultaneous
physical owners.

## Radio path

The HT-RA62 contains its RF switch and oscillator control. The E290 radio owner
therefore:

- selects the SX1262 high-power variant and DC-DC regulator;
- enables DIO2 RF-switch control;
- configures DIO3 TCXO control for 1.8 V;
- uses the module's direct PA rather than an external front-end gain model; and
- keeps RNode framing, continuous receive, CAD, transmit, and cancellation
  inside the sole radio owner.

The default erased profile is 915 MHz, 125 kHz bandwidth, SF7, coding rate 4/5,
a 24-symbol preamble, explicit header, CRC, normal IQ, and requested +14 dBm.
The app can atomically save frequency, bandwidth, spreading factor, coding rate,
and one of these requested SX1262 power rows for the next reboot:

| Requested output | SX1262 `SetPaConfig` |
| ---: | --- |
| +14 dBm | `02/02/00/01` |
| +17 dBm | `02/03/00/01` |
| +20 dBm | `03/05/00/01` |
| +22 dBm | `04/07/00/01` |

These are requested chip outputs, not calibrated conducted power or antenna
EIRP. +22 dBm requires at least 3.3 V at the PA supply and a supply path capable
of the module's transmit current. Cable, regulator, battery, antenna, and
placement quality can dominate observed range.

All directly communicating LoRa nodes must use matching frequency, bandwidth,
spreading factor, and coding rate. The operator remains responsible for legal
regional operation.

A whole-operation watchdog treats a dropped RX, CAD, or TX future as destructive:
the sole owner asserts radio reset and cannot reuse its consumed SPI/GPIO driver
state. The actor first returns the exact packet completion, including the
post-exposure durability gate, then performs one RTC-marker-guarded software
reset so ordinary boot reconstructs every physical owner. A repeat within ten
minutes of that recovery boot is suppressed and leaves only LoRa fail-stopped
until a power cycle, preventing a whole-appliance reboot loop.

## Memory and flash

The ESP32-S3R8 identifies an 8 MiB PSRAM floor even though some Heltec material
uses an ambiguous 16M notation. The full firmware requires at least 8 MiB of
mapped PSRAM and 16 MiB flash. New hardware should be checked with `espflash
board-info` rather than inferred from marketing material.

PSRAM is appropriate for large protocol state, indexes, and the 4,736-byte
display framebuffer. It cannot replace internal memory required by task stacks,
the Wi-Fi/BLE controller, synchronization, interrupts, DMA, or cache-off flash
operations.

The route-diagnostics snapshot and the plain radio-trace ring are mapped-PSRAM
backing stores. Their synchronization and correlation control remains in
internal memory, and neither backing store is interrupt- or cache-off-visible.

The current flash map is documented in
[`partitions/README.md`](../../partitions/README.md).

## Display and buttons

The panel is rendered as a 296×128 landscape view. The display actor alone owns
SPI, GPIO18 panel power, the framebuffer, refresh, deep sleep, and completion
reporting. Display faults do not stop Reticulum routing, but pairing that needs
a visible passkey fails closed when the display is unavailable.

`BOOT` is GPIO0 and selects the ROM loader. The middle button marked `21` is the
application physical-presence input used for pairing and Bluetooth bond
recovery.
